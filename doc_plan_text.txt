Sugerencias ordenadas por calidad agronómica y distancia genética.

5. Cómo se verificará que el trabajo quedó bien
Criterio
Qué se revisa
Datos reales
Cada entrega se prueba con datos reales del programa, no solo con datos de prueba.
No romper lo existente
Lo que ya funcionaba debe seguir funcionando después del cambio.
Uso por el mejorador
La funcionalidad debe ser entendible y útil para el equipo de mejoramiento.
Cumplimiento SETI
El código debe cumplir calidad, seguridad, documentación y control de versiones.
Documentación
Cada cambio debe quedar explicado para usuarios y equipo técnico.
6. Riesgos principales
Riesgo
Manejo propuesto
Faltan coeficientes genéticos propios de CENICAÑA
Coordinar reunión técnica antes de septiembre. Si no están disponibles, usar valores de referencia de literatura.
Cambios en base de datos requieren aprobación
Revisar con SETI antes de cada desarrollo que implique nuevas tablas o campos.
Disponibilidad limitada del equipo
Usar noviembre como margen de ajuste y priorizar primero validaciones, errores y funciones críticas.
Pocos datos reales de floración fuera de temporada
Crear datos simulados controlados para validar la lógica sin depender de la temporada.
Este plan busca que SIVAR sea más confiable, claro y útil para el programa de mejoramiento. La prioridad es validar primero Floración y Cruzamientos, construir las mejoras que apoyan la programación de cruces y cerrar con pruebas, documentación y entrega formal.
