3. Seguridad del Sistema
Estos cuatro errores no se ven en ninguna pantalla, pero representan riesgos reales para la información del programa de mejoramiento. Son los primeros en atenderse.
🔴 S-1  La base de datos puede ser manipulada desde la URL
¿Qué pasa?  
Ciertas pantallas del sistema permiten que una persona malintencionada modifique el texto de la dirección web para ejecutar comandos sobre la base de datos de CENICAÑA.
Impacto en el programa:  
Una persona podría leer, modificar o borrar registros del programa de mejoramiento sin autorización.
¿Qué se va a hacer?  
Cambiar la forma en que el sistema recibe datos del usuario para que nunca sean ejecutados directamente en la base de datos. Es un ajuste técnico que no cambia ninguna pantalla visible.
Responsable:  
Jhon Trujillo — Sprint 1
🔴 S-2  Direcciones internas del servidor escritas en el código
¿Qué pasa?  
Las direcciones IP de los servidores internos de CENICAÑA están escritas directamente en el código del sistema, visibles para cualquiera que tenga acceso al repositorio.
Impacto en el programa:  
Exposición de la infraestructura tecnológica de CENICAÑA a personas no autorizadas.
¿Qué se va a hacer?  
Mover esas direcciones a un archivo de configuración privado que no se comparte ni se publica.
Responsable:  
Jhon Trujillo — Sprint 1
🟡 S-3  Errores internos del sistema se muestran al usuario
¿Qué pasa?  
Cuando el sistema tiene un error interno, el mensaje que aparece en pantalla contiene detalles técnicos sobre la estructura de la base de datos.
Impacto en el programa:  
Facilita el trabajo de un atacante que quiera explorar vulnerabilidades.
¿Qué se va a hacer?  
Los errores internos quedarán en un archivo de registro privado. Al usuario le aparecerá solo un mensaje genérico.
Responsable:  
Sebastian — Sprint 1
🟡 S-4  Datos de floración visibles en la consola del navegador
¿Qué pasa?  
Mientras el sistema funciona, datos de las flores activas (hacienda, variedad, proyecto) se imprimen en una consola interna del navegador que cualquier usuario técnico puede ver.
Impacto en el programa:  
Exposición de información operativa del programa de mejoramiento.
¿Qué se va a hacer?  
Eliminar esos registros automáticos. No cambia ninguna funcionalidad visible.
Responsable:  
Sebastian — Sprint 1

Este módulo tiene una mezcla de errores activos que hay que corregir y funcionalidades nuevas que hay que construir. Se presentan por separado para que quede claro cuál es cuál.
4.1 Errores a corregir
🔴 V-1  El árbol genealógico no carga
¿Qué pasa?  
Al intentar ver el árbol genealógico de cualquier variedad, el sistema falla y no muestra nada.
Impacto en el programa:  
La herramienta de trazabilidad genética del programa es completamente inutilizable.
¿Qué se va a hacer?  
Corregir el error en el servidor que impide que el árbol se construya.
Responsable:  
Jhon Trujillo — Sprint 3
🔴 V-2  El árbol genealógico muestra solo el último ancestro encontrado
¿Qué pasa?  
Aunque el árbol intenta cargarse, un error en el algoritmo hace que solo aparezca el último ancestro, sin ninguna rama intermedia.
Impacto en el programa:  
El pedigree completo de la variedad no es visible. No se pueden identificar ancestros comunes entre progenitores candidatos.
¿Qué se va a hacer?  
Rediseñar el algoritmo que construye el árbol para que acumule todos los niveles de ascendencia correctamente.
Responsable:  
Jhon Trujillo — Sprint 3
🔴 V-3  El historial no funciona al buscar la descendencia directa de una variedad
¿Qué pasa?  
Al seleccionar el tipo 'Cruzamientos Directos' en el historial, el sistema no retorna ningún resultado aunque los datos existan. Hay un error en la consulta a la base de datos.
Impacto en el programa:  
El mejorador no puede saber qué variedades salieron de un cruzamiento específico.
¿Qué se va a hacer?  
Corregir la consulta para que la búsqueda por descendencia funcione correctamente.
Responsable:  
Jhon Trujillo — Sprint 2
🔴 V-4  La búsqueda y el Excel del banco de germoplasma solo funcionan en la página visible
¿Qué pasa?  
El banco está dividido en páginas. La búsqueda y el Excel solo actúan sobre los registros de la página actual, ignorando todas las demás.
Impacto en el programa:  
Es imposible encontrar variedades en otras páginas. El Excel tiene solo una fracción del banco.
¿Qué se va a hacer?  
Conectar la búsqueda al servidor para que revise todo el banco. Crear exportación Excel con todos los registros.
Responsable:  
Jhon Trujillo + Sebastian — Sprint 5
4.2 Funcionalidades nuevas a construir
🟢 V-A  El árbol genealógico diferenciará visualmente madre y padre
¿Por qué se necesita?  
Hoy todos los nodos del árbol se ven iguales. Es difícil leer quién fue la madre y quién fue el padre en cada generación.
¿Qué podrá hacer el sistema?  
Los nodos de madres se mostrarán en rosado y los de padres en azul. También se agregarán etiquetas de generación (F1, F2, etc.) para facilitar la lectura del pedigree.
Responsable:  
Sebastian — Sprint 3
🟢 V-B  El historial de variedad mostrará los resultados agronómicos obtenidos en cada etapa
¿Por qué se necesita?  
Hoy el historial lista los cruzamientos en que participó la variedad, pero no muestra qué resultados obtuvo en campo: rendimiento, sacarosa, resistencia a enfermedades.
¿Qué podrá hacer el sistema?  
El historial incluirá los promedios de rendimiento, sacarosa, mosaico y carbón en cada etapa del programa, permitiendo ver la trayectoria completa de la variedad.
Responsable:  
Jhon Trujillo — Sprint 4
🟢 V-C  El banco de germoplasma tendrá filtros avanzados por mega ambiente y características
¿Por qué se necesita?  
Hoy solo hay búsqueda por texto libre. El mejorador tiene que revisar visualmente cientos de registros para encontrar candidatos.
¿Qué podrá hacer el sistema?  
Habrá filtros por mega ambiente (Seco-Semiseco, Húmedo, Piedemonte) y por rangos numéricos de TCHM, Sacarosa, Mosaico y Carbón. Los valores de enfermedades tendrán colores: verde (resistente), amarillo (tolerante), rojo (susceptible).
Responsable:  
Jhon Trujillo + Sebastian — Sprint 5
🟢 V-D  El sistema alertará cuando dos progenitores están emparentados
¿Por qué se necesita?  
Hoy no hay ninguna herramienta que detecte si dos variedades candidatas a progenitores comparten ancestros comunes. Cruzar variedades emparentadas reduce el vigor de la descendencia.
¿Qué podrá hacer el sistema?  
Al configurar el cruzamiento, el sistema calculará automáticamente el nivel de parentesco entre los dos progenitores elegidos y mostrará una alerta cuando el parentesco supere el umbral crítico.
Responsable:  
Jhon Trujillo — Sprint 8
5. Módulo de Floración
✅  Este módulo no tiene errores pendientes
Los problemas que tenía el módulo de floración ya fueron revisados y corregidos en la fase anterior. Lo que se presenta a continuación son funcionalidades completamente nuevas que nunca existieron y que mejorarán significativamente el trabajo del técnico de campo.
5.1 Funcionalidades nuevas a construir
🟢 F-A  El sistema calculará y usará la viabilidad del polen
¿Por qué se necesita?  
Hoy el sistema registra los conteos de granos de polen por muestra pero nunca calcula el porcentaje de viabilidad. Se puede sugerir un macho con polen no funcional y el cruzamiento falla.
¿Qué podrá hacer el sistema?  
Se calculará el porcentaje de viabilidad con los datos ya registrados. Si es menor al 10%, ese macho se bloqueará automáticamente como progenitor. Si está entre 10% y 20%, aparecerá una advertencia. El indicador será visible en la lista de floración con colores (verde/amarillo/rojo).
Responsable:  
Jhon Trujillo + Sebastian — Sprint 6
🟢 F-B  El sistema verificará que madre y padre están floreciendo al mismo tiempo
¿Por qué se necesita?  
Un cruzamiento solo es posible si hembra y macho están activos simultáneamente. Hoy no se verifica este solapamiento. Se pueden programar cruzamientos imposibles.
¿Qué podrá hacer el sistema?  
Antes de mostrar una combinación como viable, el sistema verificará que las fechas de floración activa se solapen. Se agregará un diagrama visual que muestre las ventanas de floración por variedad.
Responsable:  
Jhon Trujillo — Sprint 7
🟢 F-C  La lista de floración tendrá filtros para el trabajo diario
¿Por qué se necesita?  
Hoy se muestran todas las flores de todos los proyectos mezcladas. El técnico pierde tiempo revisando información que no le corresponde.
¿Qué podrá hacer el sistema?  
Habrá filtros por sexo (hembra/macho), proyecto y nivel de viabilidad del polen. Cada flor tendrá un indicador de frescura según cuántas horas lleva activa: verde (<12h), amarillo (12-24h), rojo (>24h).
Responsable:  
Sebastian — Sprints 6 y 7
🟢 F-D  El sistema identificará variedades con comportamiento sexual inestable
¿Por qué se necesita?  
Algunos tratamientos de inducción pueden cambiar el sexo de una flor. El sistema registra estos cambios pero nunca los analiza. Un progenitor con historial de cambios frecuentes hace el cruzamiento impredecible.
¿Qué podrá hacer el sistema?  
En el perfil de cada variedad se mostrará el historial de cambios de sexo. En la matriz de cruzamientos aparecerá una advertencia si un progenitor tiene alto porcentaje de cambios registrados.
Responsable:  
Jhon Trujillo — Sprint 7
6. Módulo de Programación de Cruzamientos
✅  Los errores críticos del motor de cálculo ya están corregidos
En la fase anterior se identificaron y corrigieron 5 errores graves que hacían que casi todos los cruzamientos aparecieran como inviables aunque los progenitores fueran excelentes: calificación del padre en casillero equivocado, búsqueda de datos por posición incorrecta, contaminación entre características, condición de sexo incompleta y roya sin efecto en el puntaje. Todas estas correcciones ya están en el sistema actual.
6.1 Funcionalidades nuevas a construir
🟢 C-A  El sistema tendrá un puntaje único de calidad para cada combinación
¿Por qué se necesita?  
Hoy el sistema calcula por separado qué tan buena es la madre y qué tan bueno es el padre, pero no genera un puntaje único de la combinación. Tampoco considera que en caña de azúcar cada característica se transmite de padres a hijos con diferente intensidad.
¿Qué podrá hacer el sistema?  
Cada celda de la matriz mostrará un puntaje combinado del cruzamiento que refleja la calidad esperada de la descendencia, considerando la capacidad de transmisión de cada característica. Facilita ordenar los cruzamientos de mejor a peor.
Responsable:  
Jhon Trujillo + Sebastian — Sprint 9
🟢 C-B  Un progenitor con muy alta susceptibilidad a una enfermedad bloqueará el cruzamiento
¿Por qué se necesita?  
El sistema actual evalúa la suma de los niveles de ambos progenitores. Si uno tiene susceptibilidad máxima (nivel 9) pero el otro es muy resistente (nivel 1), la suma puede no superar el límite y el cruzamiento pasa como viable, aunque el progenitor crítico transmitirá esa vulnerabilidad.
¿Qué podrá hacer el sistema?  
Se agregará una regla adicional: si cualquiera de los dos progenitores tiene nivel 8 o 9 en enfermedades críticas como mosaico o carbón, el cruzamiento se bloqueará. El mejorador verá exactamente qué enfermedad causó el bloqueo.
Responsable:  
Jhon Trujillo + Sebastian — Sprint 9
🟢 C-C  La lista de cruzamientos tendrá filtros y mostrará los resultados obtenidos
¿Por qué se necesita?  
Hoy la lista no tiene filtros por campaña ni por combinación de progenitores, y no muestra si el cruzamiento produjo semilla viable.
¿Qué podrá hacer el sistema?  
Habrá filtros por año y por combinación madre-padre. Cada cruzamiento mostrará los gramos de semilla obtenidos y las plántulas generadas.
Responsable:  
Jhon Trujillo + Sebastian — Sprint 10
🟢 C-D  La distancia genética entre progenitores influirá en las sugerencias del sistema
¿Por qué se necesita?  
Hoy la distancia genética se muestra como dato informativo pero no se usa para decidir qué combinaciones son más prometedoras. Progenitores genéticamente distantes generan mayor vigor en la descendencia.
¿Qué podrá hacer el sistema?  
Las sugerencias de cruzamientos priorizarán combinaciones con mayor distancia genética, para maximizar el vigor híbrido esperado en la progenie.
Responsable:  
Jhon Trujillo — Sprint 10

El diseño puede quedar con datos contradictorios: tratamientos registrados pero con conteos de plantas incorrectos.

7.2 Funcionalidades nuevas a construir
🟢 E-A  El libro de campo calculará el rendimiento relativo al testigo
¿Por qué se necesita?  
Hoy los clones se comparan con rendimientos brutos, sin corregir la variación natural del suelo entre parcelas. Esto hace que las comparaciones entre tratamientos sean menos precisas.
¿Qué podrá hacer el sistema?  
El libro de campo calculará el rendimiento de cada clon en relación con el testigo del mismo bloque, corrigiendo las diferencias de suelo. Las decisiones de selección serán más justas y precisas.
Responsable:  
Jhon Trujillo — Sprint 12
🟢 E-B  El sistema generará automáticamente un ranking de clones candidatos
¿Por qué se necesita?  
Hoy los clones candidatos a pasar al siguiente estado del programa se evalúan carácter por carácter sin un criterio integral de decisión.
¿Qué podrá hacer el sistema?  
El mejorador podrá definir la importancia de cada característica (rendimiento, sacarosa, resistencia a enfermedades) y el sistema generará automáticamente un ranking consolidado de clones de mejor a peor para facilitar la decisión de promoción.
Responsable:  
Jhon Trujillo + Sebastian — Sprint 12

11. Riesgos que el Equipo Directivo Debe Conocer
Estos son los factores que podrían afectar el plan. Se presentan para que el director pueda anticipar decisiones o facilitar recursos cuando sea necesario.
Riesgo
¿Por qué puede ocurrir?
¿Qué se haría?
No hay documentado cuánto se transmite cada característica genética en caña de CENICAÑA
El puntaje combinado del cruzamiento (Sprint 9) necesita este dato del propio programa. Si no está disponible, el cálculo se hará con valores de la literatura científica publicada.
Coordinar con el equipo de mejoramiento ANTES de septiembre para obtener estos valores. El director debe facilitar esta reunión técnica.
Cambios necesarios en la base de datos requieren aprobación de SETI
Algunas funcionalidades nuevas (Libro de Campo, Ranking de clones) pueden requerir agregar nuevas tablas en la base de datos.
Revisar la necesidad de cambios antes de cada sprint. Incluir a SETI con suficiente anticipación para no bloquear el trabajo.
Disponibilidad del equipo por otras responsabilidades en CENICAÑA
Jhon y Sebastian pueden tener otras tareas que reduzcan los días disponibles para este proyecto.
El Sprint 13 (noviembre) funciona como margen de maniobra. Si hay retrasos, las funcionalidades más avanzadas (Ranking de clones, ajuste espacial) pueden aplazarse sin afectar las correcciones de errores críticos.
Fuera de temporada de floración hay pocos datos para probar sincronía
La herramienta de sincronía floral necesita datos de flores con diferentes fechas para probarse. Si el desarrollo cae fuera de temporada, los datos reales pueden ser escasos.
El equipo creará datos de prueba simulados con diferentes fechas para validar la lógica, independientemente de la temporada real.
